# Design System

## 1. Общее направление

Интерфейс должен быть современным, минималистичным и спокойным.

Визуальные ориентиры:

* Notion;
* ChatGPT;
* Linear;
* современные SaaS-продукты.

Нужно использовать их общие принципы, но не копировать конкретные экраны или компоненты.

Основные характеристики:

* только светлая тема;
* много свободного пространства;
* простая визуальная иерархия;
* минимум декоративных элементов;
* акцент на контенте;
* тонкие границы;
* почти полное отсутствие тяжёлых теней;
* небольшое количество акцентных цветов;
* единообразные компоненты;
* высокая плотность информации без ощущения перегруженности.

Интерфейс не должен выглядеть как типичный лендинг онлайн-школы.

Не использовать:

* крупные градиенты;
* стеклянные эффекты;
* неон;
* тяжёлые тени;
* слишком большие скругления;
* разноцветные карточки;
* декоративные 3D-элементы внутри рабочих интерфейсов;
* чрезмерно крупную типографику;
* случайные иллюстрации;
* разные стили кнопок на разных страницах.

# 2. Бренд

Название продукта:

**Дизайн Тусовка**

Основной цвет:

**Primary Blue — `#094BF5`**

Primary используется для:

* основных кнопок;
* активных пунктов навигации;
* ссылок;
* выбранных элементов;
* прогресса;
* focus-состояний;
* ключевых иконок;
* небольших визуальных акцентов.

Primary не должен заливать большие площади интерфейса.

# 5. Сетка и контейнеры

## Desktop

* максимальная ширина основного контента: 1280 px;
* максимальная ширина текстового материала: 760 px;
* боковая панель: 240–280 px;
* отступ страницы: 32 px;
* расстояние между колонками: 24 px.

## Tablet

* горизонтальные отступы: 24 px;
* sidebar скрывается или открывается отдельно;
* карточки перестраиваются в две колонки.

## Mobile

* горизонтальные отступы: 16 px;
* одна колонка;
* меню открывается поверх контента;
* действия покупки могут фиксироваться снизу.

# 6. Система отступов

Основной шаг:

**4 px**

Основные значения:

* 4 px;
* 8 px;
* 12 px;
* 16 px;
* 20 px;
* 24 px;
* 32 px;
* 40 px;
* 48 px;
* 64 px;
* 80 px.

Чаще всего используются:

* 8 px между связанными элементами;
* 12 px внутри компактных компонентов;
* 16 px внутри контролов;
* 20–24 px внутри карточек;
* 32 px между секциями;
* 48–64 px между крупными блоками страницы.

---

# 7. Скругления

Интерфейс должен быть менее округлым, чем ранние концепты.

* небольшие элементы: 6 px;
* кнопки и поля: 8 px;
* карточки: 12 px;
* крупные панели: 16 px;
* бейджи: 999 px;
* модальные окна: 16 px.

Не использовать радиус 24–32 px для обычных карточек.

---

# 8. Границы и тени

## Границы

Основной способ разделения элементов — граница `1 px`.

Основная граница:

`#E7E7E7`

Активная граница:

`#094BF5`

Ошибка:

`#F04438`

## Тени

Тени используются только для:

* dropdown;
* modal;
* popover;
* tooltip;
* плавающих панелей.

Обычные карточки должны использовать границу без тени.

Основная тень плавающих элементов:

`0 8px 30px rgba(0, 0, 0, 0.08)`

Лёгкая тень:

`0 2px 8px rgba(0, 0, 0, 0.06)`

---

# 9. Иконки

Используется единый набор:

**Lucide Icons**

Требования:

* размер по умолчанию: 16 px;
* крупные иконки: 20 или 24 px;
* толщина линии: 1.75–2 px;
* цвет соответствует тексту;
* не смешивать разные библиотеки иконок;
* не использовать emoji вместо системных иконок.

* кнопка сохраняет ширину;
* текст заменяется или дополняется spinner;
* повторное нажатие блокируется.

# 12. Карточки

Карточки используются только там, где объект действительно является отдельной сущностью.

Не оборачивать каждый блок страницы в карточку.

## Карточка материала

Содержит:

* обложку;
* тип материала;
* название;
* короткое описание;
* длительность;
* уровень;
* цену;
* рейтинг;
* сохранение;
* прогресс пользователя.

## Карточка задания

Содержит:

* тип задания;
* название;
* описание;
* сложность;
* время;
* цену;
* наличие проверки;
* текущий статус.

## Визуальные требования

* белый фон;
* граница Neutral 300;
* радиус 12 px;
* padding 16–20 px;
* без постоянной тени;
* hover: граница становится темнее;
* интерактивная карточка может немного менять фон;
* никакого заметного увеличения карточки при hover.

---

# 13. Sidebar

Sidebar используется:

* в личном кабинете;
* в ридере;
* в админке.

Требования:

* ширина 240–280 px;
* светло-серый фон;
* тонкая правая граница;
* компактные пункты меню;
* иконка 16–18 px;
* активный пункт выделяется светло-синим фоном;
* текст активного пункта — Primary;
* секции могут сворачиваться;
* нижняя часть используется для профиля и настроек.

Sidebar должен быть ближе к ChatGPT и Notion, чем к классической тяжёлой админке.

---

# 14. Header

Header должен быть компактным.

Высота:

56–64 px.

Содержит:

* логотип;
* основную навигацию;
* поиск;
* действия пользователя;
* профиль.

Требования:

* белый фон;
* нижняя граница;
* без тени;
* sticky допускается;
* на mobile превращается в компактную панель.

---

# 15. Таблицы

Таблицы используются в админке.

Требования:

* высота строки 44–52 px;
* заголовок таблицы на светло-сером фоне;
* тонкие горизонтальные разделители;
* минимум вертикальных линий;
* hover строки;
* checkbox для массовых действий;
* сортировка;
* фильтры;
* пагинация;
* меню действий;
* empty state;
* skeleton loading.

На mobile таблицы могут превращаться в список карточек.

---

# 16. Состояния интерфейса

Для каждой страницы и компонента должны быть предусмотрены:

* loading;
* empty;
* error;
* success;
* disabled;
* no access;
* not found;
* offline или ошибка соединения.

Не использовать spinner как единственное состояние загрузки больших страниц.

Для контента используются skeleton-компоненты.

---

# 17. Обратная связь

## Toast

Используется для коротких сообщений:

* сохранено;
* скопировано;
* отправлено;
* произошла ошибка.

## Alert

Используется внутри страницы для важной информации.

## Modal

Используется только для:

* подтверждения опасного действия;
* короткой формы;
* выбора;
* покупки;
* системного сообщения.

Не использовать modal для длинного контента.

---

# 18. Анимации

Анимации должны быть почти незаметными.

Основная длительность:

* 120–180 ms для hover;
* 180–240 ms для открытия;
* до 300 ms для modal и sidebar.

Разрешены:

* opacity;
* небольшое изменение background;
* небольшое перемещение;
* раскрытие блоков.

Не использовать:

* bounce;
* сильный scale;
* сложные пружинные анимации;
* декоративные переходы между страницами.

---

# 19. Доступность

Обязательные требования:

* контраст текста не ниже WCAG AA;
* заметное focus-состояние;
* управление клавиатурой;
* корректные labels;
* aria-label для кнопок без текста;
* размер зоны нажатия не меньше 40 px;
* ошибки не обозначаются только цветом;
* изображения имеют alt;
* модальные окна удерживают focus;
* Escape закрывает modal и dropdown.

---

# 20. Использование референсных скриншотов

Референсные скриншоты используются только для понимания:

* структуры страниц;
* состава блоков;
* расположения элементов;
* визуальной плотности;
* общей композиции;
* сценариев интерфейса.

Необходимо игнорировать в скриншотах:

* оранжевый цвет;
* случайные HEX;
* случайные размеры;
* случайные тексты;
* ошибки генерации;
* декоративные элементы, противоречащие текущей системе.

Для финального интерфейса используются только цвета, типографика, размеры, радиусы и состояния, описанные в этом документе.

Главный акцент проекта всегда:

`#094BF5`

Референсные изображения не являются готовыми макетами для точного копирования.

---

# 21. Общие ограничения

Все страницы должны использовать единую систему компонентов.

Нельзя:

* создавать новый стиль кнопки для отдельной страницы;
* использовать случайные цвета;
* добавлять inline-стили без необходимости;
* использовать разные радиусы;
* использовать разные размеры одинаковых компонентов;
* копировать компоненты вместо переиспользования;
* добавлять тяжёлые тени;
* добавлять лишние карточки;
* менять дизайн-систему без явного решения.

Любое новое визуальное решение должно сначала добавляться в дизайн-систему, а затем использоваться на страницах.
