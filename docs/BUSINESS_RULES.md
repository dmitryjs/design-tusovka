# Business Rules

Утверждённые бизнес-правила платформы «Дизайн Тусовка». Источник истины — требования этапа 1.1 и `PRODUCT.md`.

## Авторизация и аккаунт

| ID | Правило |
|----|---------|
| AUTH-01 | Регистрация и вход: email + пароль и Google OAuth; восстановление пароля. |
| AUTH-02 | Пароли не хранятся в приложении — Supabase Auth. |
| AUTH-03 | Email подтверждён **до** оплаты заказа. |
| AUTH-04 | Email подтверждён **до** отправки решения задания. |
| AUTH-05 | Google OAuth и email+пароль с одним email → **один** аккаунт. |
| AUTH-06 | Удаление аккаунта только через поддержку; деактивация; данные заказов, оплат и чеков сохраняются. |

## Доступ к контенту

| ID | Правило |
|----|---------|
| ACCESS-01 | Цена, доступ и статус оплаты с клиента **не доверяются**. |
| ACCESS-02 | Платный контент — доступ **только** после серверного подтверждения оплаты. |
| ACCESS-03 | Success URL **не** подтверждает оплату. |
| ACCESS-04 | Доступ к купленным материалам и разделам — **бессрочный**. |
| ACCESS-05 | Обновления уже купленных материалов — **бесплатны**. |
| ACCESS-06 | Платный материал до покупки: описание и содержание, **не** текст глав. |
| ACCESS-07 | Покупка раздела открывает материалы, входившие в него **на момент покупки**. |
| ACCESS-08 | Новые материалы в разделе — через платное обновление раздела. |
| ACCESS-09 | Платное задание в библиотеке — после покупки. |
| ACCESS-10 | Бесплатное задание в библиотеке — после **первой отправки** решения. |
| ACCESS-11 | Приватные файлы Storage — доступ после серверной проверки прав. |

## Материалы

| ID | Правило |
|----|---------|
| MAT-01 | Материал принадлежит **одному** разделу. |
| MAT-02 | Типы: мини-гайд, полный гайд, конспект, чек-лист, шаблон, шпаргалка, урок, практика. |
| MAT-03 | Статусы: черновик, опубликован, скрыт. |
| MAT-04 | Удаление навсегда — только если товар **никто не покупал**. |
| MAT-05 | Контент: главы на одной странице; чтение на сайте; возможны скачиваемые вложения. |

## Разделы

| ID | Правило |
|----|---------|
| SEC-01 | Раздел = категория каталога + покупаемый набор материалов; задания не входят. |
| SEC-02 | Цена раздела задаётся администратором вручную. |
| SEC-03 | Из цены раздела вычитается сумма, **фактически заплаченная** за уже купленные материалы из этого раздела. |
| SEC-04 | Если пользователь владеет всеми текущими материалами раздела — раздел считается купленным автоматически. |
| SEC-05 | Покупка последнего обновления раздела открывает все пропущенные новые материалы. |
| SEC-06 | Доступное обновление: метка на карточке + баннер в библиотеке. |

## Корзина

| ID | Правило |
|----|---------|
| CART-01 | Гость собирает корзину **локально**. |
| CART-02 | После авторизации гостевая корзина **объединяется** с корзиной аккаунта; дубли удаляются. |
| CART-03 | Корзина авторизованного пользователя синхронизируется между устройствами. |
| CART-04 | Уже купленный товар повторно добавить **нельзя**. |
| CART-05 | Материал, доступный через купленный раздел, повторно добавить **нельзя**. |
| CART-06 | Раздел + материал из него в корзине: материал **автоматически удаляется**; показывается объяснение; кнопка «Оставить материал»; перед оплатой — повторное предупреждение. |
| CART-07 | Товар снят с продажи — удаляется из корзины с уведомлением. |
| CART-08 | При изменении цены на checkout — **актуальная** цена + уведомление. |
| CART-09 | Платные и бесплатные позиции могут быть в одной корзине. |
| CART-10 | Один заказ оплачивается **только целиком**. |
| CART-11 | CTA для бесплатных позиций: **«Получить бесплатно»**. |

## Заказы

| ID | Правило |
|----|---------|
| ORDER-01 | Сумма пересчитывается и проверяется на сервере перед платежом. |
| ORDER-02 | Бесплатный товар — заказ на **0 ₽**; после оформления — доступ в библиотеку. |
| ORDER-03 | История заказов в профиле авторизованного пользователя. |
| ORDER-04 | При отмене/ошибке оплаты корзина **сохраняется**; следующая попытка — **новый** заказ. |
| ORDER-05 | Базовые цены хранятся в **рублях**; подписки и промокоды **отсутствуют**. |

## Платежи

| ID | Правило |
|----|---------|
| PAY-01 | Оплата только после авторизации и подтверждения email. |
| PAY-02 | Способы: ЮKassa; СБП по QR-коду; криптопроцессинг с автоматическим подтверждением. |
| PAY-03 | Секреты только на сервере; данные карт не сохраняются. |
| PAY-04 | Webhook **идемпотентен**; повторный webhook не выдаёт доступ повторно. |
| PAY-05 | При задержке webhook — UI «Платёж подтверждается»; сервер перепроверяет статус. |
| PAY-06 | Если оплата подтверждена, а доступ не выдан — повторная выдача; ошибка в админке. |
| PAY-07 | Крипто: показ рублёвой цены и эквивалента USDT; курс фиксируется на срок счёта. |
| PAY-08 | Интеграция по **актуальной официальной документации** провайдера. |
| PAY-09 | Платежи принимает ИП на УСН «Доходы»; чеки — решение ЮKassa для 54-ФЗ (конфигурация на этапе 10). |

## Возвраты

| ID | Правило |
|----|---------|
| REF-01 | Автоматического интерфейса возвратов **нет**. |
| REF-02 | Запрос на email поддержки с причиной и доказательствами. |
| REF-03 | Решение — администратор вручную. |
| REF-04 | После подтверждённого возврата доступ отзывается; если доступ остаётся через другую покупку — сохраняется. |
| REF-05 | Раздел возвращается **только целиком**. |
| REF-06 | Юридические условия — в оферте (**текст TBD**). |

## Задания и проверка

| ID | Правило |
|----|---------|
| TASK-01 | Черновики решения **не сохраняются**. |
| TASK-02 | Отправка: ссылка Figma/FigJam, файлы, комментарий. |
| TASK-03 | AI (Polza AI): бесплатно; **1 попытка** на пользователя на задание; техошибка не расходует попытку. |
| TASK-04 | AI файлы: 1 PDF до 20 МБ **или** до 10 PNG/JPG до 10 МБ каждый; нечитаемые не отправляются в AI. |
| TASK-05 | AI критерии — список без весов; результат без баллов; бессрочно в профиле. |
| TASK-06 | Ручная проверка: оплата на финальном шаге отправки; **не** в корзине; после оплаты — автоотправка. |
| TASK-07 | Ручная: 1 проверка + 1 повторная отправка; 1 ссылка, комментарий, до 5 файлов по 50 МБ. |
| TASK-08 | Ручная: черновик, превью, редактирование с версиями; старые версии сохраняются; очередь без SLA. |
| TASK-09 | В MVP ручные проверки выполняет **владелец** через админку. |
| TASK-10 | **Цена ручной проверки — TBD.** |

## Отзывы

| ID | Правило |
|----|---------|
| REV-01 | Отзывы для материалов, заданий и разделов. |
| REV-02 | Оставить может только получивший/купивший товар; для раздела — только купивший раздел **целиком**. |
| REV-03 | Один пользователь — один отзыв на товар. |
| REV-04 | Оценка 1–5 + текст; пользователь может редактировать и удалять. |
| REV-05 | Публикуются **сразу**; администратор может **скрыть**. |

## Безопасность

| ID | Правило |
|----|---------|
| SECU-01 | Проверка прав на сервере для чувствительных операций. |
| SECU-02 | Секреты не в клиенте и Git; примеры — `.env.example`. |

## Статусы (для этапа 3)

- **Материал:** черновик | опубликован | скрыт
- **Заказ:** ожидает оплаты | оплачен | отменён | ошибка | выполнен (0 ₽) — уточнить enum на этапе 3
- **Платёж:** по статусам API провайдера
- **Доступ:** активен (бессрочно); отозван при возврате
- **Ручная проверка:** черновик | в очереди | на проверке | опубликована | требуется доработка — уточнить на этапе 13
